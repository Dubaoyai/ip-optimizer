feat(icon): 矢量程序图标 + 新建中枢「图标工坊」技能

用户需求：「去生成一个牛逼的图标换上」「你去找个专门来制作图标的技能来，还有头像呀这种来使用」

## 1. 中枢新增技能：icon-studio（图标工坊）

唯一入口：图标 / 头像 / favicon 制作。

核心判据：图标只在 16px 下验货 —— AI 生成的 1024px 大图有手绘质感与渐变，
缩到 16px（任务栏/文件夹实际尺寸）会糊成一团。这是图标设计的固有难题，不是画质不够。
工坊的解法是矢量重绘：纯几何形状构造同一意象，线条可按尺寸加粗、保持纯色，
16px 下仍锐利。

技能组成：
- 图标工坊.py —— 矢量绘制 + 多尺寸 ICO/PNG 导出 + 双校验（小尺寸可辨识性 + 构图）
- 自检-构图探针反向验证.py —— 证明构图探针不是恒真的废判据
- SKILL.md —— 工作流 + 设计规范 + 踩坑记录
- 3 个矢量预设：signal（信号波纹）/ bolt（闪电）/ shield（盾牌+对勾）

建档依据：先数实例 —— 经验库 3 条 + 台账 11 条命中「图标/ico/favicon」，
且无现成技能覆盖，满足「实例 >= 3 才建」的量化线。

## 2. IP优化器换上矢量图标

assets/app.ico（30.8 KB，含 16/24/32/48/64/128/256 七档），
用 signal 预设 + 程序主题配色（#7c6cf0 紫 / #181818 深灰底）。

设计选择依据：与程序「网络测速优选」语义契合；纯几何无渐变，16px 下点与弧仍清晰。

装入两处：
- IP-Optimizer.spec：icon="assets/app.ico" → exe 文件图标（资源管理器/任务栏）
- main.py：新增 _apply_app_icon() → 运行时窗口图标
  （路径同时适配源码运行与打包运行，从 sys._MEIPASS 取）

spec 的 datas 只打 assets/app.ico 单文件，不用整目录，
避免把多版候选图（几百 KB x N）打进 exe。

## 3. 开发中踩到并修正的三个坑（均已写入 SKILL.md）

1. 透明判定不能用 alpha == 0 —— 抗锯齿边缘的 alpha 是 2~5 这类小值，
   用 == 0 会漏掉它们，导致构图报告误报「四边留白全 0、主体被切断」。
   该 bug 连续两次改判据均未修复，第三次靠「打印实际扫描到的像素」才定位。
   定版判据：alpha < 128 视为画布外空白。
2. getbbox() 在合成图上恒等于整块画布（含圆角底板，非透明区铺满），
   判「是否被切断」必须按「与背景色的差异」找主体像素。
3. 目测缩略图会误判构图 —— 我曾据缩略图断定「弧被右缘切断」并改小半径，
   后被 getbbox() 实测（四边留白 0.24/0.22/0.22/0.24，均衡无切断）证伪，
   遂改回原参数。构图问题看归一化留白值，不看缩略图观感。

## 4. 验证证据（可复算）

- 构图探针反向验证：造「正常/故意越界/故意失衡」三用例，
  探针全部判对（正常放行、越界报切断、失衡报不均衡），非恒真废判据
- 三个预设的构图报告：signal 均衡、bolt 均衡（判据已正确区分纵向形状的天然比例）、
  shield 均衡
- 小尺寸可辨识性：16/24/32/48px 主体占比 15~16%，全部「清晰」
- 图标运行时加载：QIcon.availableSizes() 返回 7 档全部可用
- exe 内嵌图标：SHGetFileInfoW 取到图标句柄
- exe 独立运行（空白目录）：进程存活、主窗口创建、日志显示从 _MEIPASS 读到图标
- 回归：pytest 156 passed

## 5. 一处环境问题（已处理）

打包首次失败：PermissionError 拒绝访问 dist\IP-Optimizer-V1.5.exe，
根因是我此前验证时残留了两个 exe 进程（PID 4016/7144）占用文件。
终止进程后打包正常。教训：验证完 exe 必须确保进程退出，否则会卡住下一次打包。
