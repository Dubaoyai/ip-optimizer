# 数码解码 IP 优选器 V1.4

一个 Windows 桌面版的 IP 优选测速工具（Python + PySide6）。

当前已包含的功能（自动获取 IP + 三级测速 + 综合评分排名 + 稳定性复测）：

> TXT / 粘贴 / **自动获取 Cloudflare IP** → IP 验证 → **TCP 测速 → HTTP 测速 → 下载测速** → 并发测速 → **综合评分排名（TOP100 / 筛选）** → **稳定性复测（多轮重测）** → 界面显示结果 → 一键复制 / 导出 → 支持中途停止

V1.1 新增：**自动获取更多 IP**——软件自动请求 Cloudflare 官方公开 IPv4 网段（CIDR），
从网段中随机抽取候选 IP（不会遍历整个网段），自动去重、过滤后加入当前 IP 列表。

V1.2 新增：**TCP → HTTP → 下载 三级测速流程**——
1. TCP 443 握手测延迟（V1.1 已有）；
2. TCP 通过后发起 HTTPS 请求，测 HTTP 状态码与响应延迟；
3. HTTP 通过后下载固定大小数据（默认 1 MB），统计下载速度。

三个阶段逐级瀑布：**前一级失败，后面的阶段自动跳过**，不浪费流量与时间。

V1.3 新增：**综合评分 / 排名 / 筛选 / 一键复制 / 导出**——
测速结束后所有成功 IP 得到 0~100 的综合评分并按评分排名，可筛选最低速度与最大延迟、
只看 TOP10/20/50/100，一键复制或导出 TXT / CSV。

V1.4 新增：**稳定性复测**——对 V1.3 排名中的 TOP IP **重复测试多轮**（默认 5 轮），
统计成功率与波动（变异系数 CV），算出每个 IP 的**稳定性评分**与**最终评分**：

```text
最终评分 = V1.3 综合评分 × 0.9 + 稳定性评分 × 0.1
```

复测后表格按最终评分重新排名，**「一次快、多次抖」的 IP 会被排到后面**，
稳定可用的 IP 排到前面；V1.3 的评分与排名完全保留（表格里仍能看到）。

## 1. 项目介绍

| 项目 | 说明 |
| --- | --- |
| 名称 | 数码解码 IP 优选器 V1.4 |
| 类型 | Windows 桌面软件（GUI） |
| 用途 | 批量导入 IP，通过 TCP → HTTP → 下载 三级测速 + 稳定性复测找出又快又稳的 IP |
| 测速方式 | 三级流水：TCP 握手（默认 443 / 1000ms）→ HTTPS 连通（默认 3000ms）→ 下载 1MB（默认 10000ms） |
| 并发方式 | asyncio 异步并发，默认并发 50，最多 500 |
| 数据存储 | 不联网上传、不使用数据库、不收集个人信息 |

第一阶段**不使用**：MySQL、Redis、Docker、Web 服务器、用户系统、账号登录、会员系统。
所有功能都在本机运行，不会修改系统网络设置、不会修改 DNS。

## 6. 如何导入 IP

界面上的 **IP 来源** 区域提供两种方式：

### 方式一：选择文件

1. 点击 **【选择IP文件】**，选择 TXT 文件
2. 点击 **【导入IP】**，程序会导入文件内容

文件内容示例（每行一个）：

```text
104.16.0.1
104.16.0.2:443
104.16.0.3
```

支持 `IP` 和 `IP:端口` 两种写法；端口不写时使用界面上设置的端口。

### 方式二：直接粘贴

1. 在文本框中粘贴 IP（每行一个）
2. 点击 **【导入IP】**（注意：如果已经选择了文件，会优先导入文件）

### 方式三：自动获取 Cloudflare IP

不想自己准备 IP？点击 **【自动获取IP】**，软件会自动拿到一批公网候选 IP：

1. 在弹出的对话框中选择 **候选IP数量**（100 / 500 / 1000 / 3000 / 5000 / 10000，默认 1000）
2. 点击 **【开始获取】**
3. 软件请求 Cloudflare 官方公开接口（`https://api.cloudflare.com/client/v4/ips`）拿到官方 IPv4 网段（CIDR）
4. 从这些网段中**随机抽取**指定数量的 IPv4（按需生成，不会遍历整个网段）
5. 自动去重、自动过滤（私有 / 回环 / 非法地址）
6. 新 IP **追加加入当前 IP 列表**（界面上「读取数量 / 有效IP」等统计随之更新）
7. 获取完成后**不会自动开始测速**，需要你自己点击 **【开始测速】**

获取完成后，对话框和界面会显示：

```text
IP来源：Cloudflare 官方
CIDR数量：15
候选IP：1000
有效IP：1000
重复IP：0
获取耗时：0.8 秒
```

#### 获取失败怎么办？先点「测试Cloudflare连接」

对话框里有一个 **【测试Cloudflare连接】** 按钮。它**只测试能不能连上 Cloudflare 官方接口**，
不会生成任何 IP：

1. 点击 **【测试Cloudflare连接】**
2. 成功时状态栏显示：
   ```text
   状态：Cloudflare API 连接正常（HTTP 200，IPv4 CIDR 15 个，耗时 759 ms，来源：主源(JSON API)）
   ```
3. 失败时显示具体原因（中文 + 真实错误），例如：
   ```text
   连接失败：网络连接错误（本机配置了系统代理 127.0.0.1:1819：请确认代理软件已启动）
   连接失败：HTTP 状态码：503
   连接失败：网络连接超时
   ```

> **重要**：本程序会**自动使用系统代理**（和浏览器一致）。
> 如果你本机装了代理软件（如 Clash / v2ray 等），
> **必须先启动代理软件**，否则程序连不上 Cloudflare（这是最常见的失败原因）。
> 详细排查方法见下文「10. 常见错误」。

### 刷新IP（重新随机一批）

点击 **【刷新IP】**：用上次设置的候选数量重新请求 Cloudflare 网段、重新随机生成候选 IP，
并与当前列表自动去重（只会补充新 IP，不会产生重复）。同样不会自动开始测速。

> ⚠️ **重要说明**：自动获取的 IP 来自 Cloudflare 官方公开 IPv4 网段，是「官方网段内的随机抽样」。
> 随机抽到的 IP **是否适合你当前的网络环境，需要实际测速确认**——请以测速结果为准。

### 导入时的自动处理

- 自动跳过空行和注释行（以 `#`、`//`、`;` 开头）
- 自动去重（同一个 IP + 同一个端口只保留一条）
- 自动过滤：非法 IP、IPv6、私有地址、回环地址、链路本地地址等
- 手动导入完成后会弹窗显示：

```text
读取数量：1000
去重后数量：900
重复数量：100
格式错误：0
有效 IP：850
无效 IP：150
```

> 数量关系：`读取数量 = 有效 IP + 重复数量 + 无效 IP`

## 7. 如何测速

1. 在 **测速设置** 中填写：
   - **端口**：默认 `443`
   - **并发**：默认 `50`（范围 1 ~ 500）
   - **超时**：默认 `1000 ms`（范围 100 ~ 60000，TCP 阶段使用）
   - **HTTP 测试**：勾选后进行 HTTPS 连通性测试，超时默认 `3000 ms`（V1.2 新增）
   - **下载测试**：勾选后下载固定大小数据测速度，大小默认 `1 MB`、超时默认 `10000 ms`（V1.2 新增）
2. 点击 **【开始测速】**
3. 观察 **测试进度** 区域：进度条、已测试 / 成功 / 失败 / 用时，以及三行**阶段统计**：
   - `TCP 成功 X / 失败 Y`
   - `HTTP 成功 X / 失败 Y / 未测试 Z`（未测试 = TCP 失败而被跳过的数量）
   - `下载 成功 X / 失败 Y / 未测试 Z`（未测试 = TCP 或 HTTP 失败而被跳过的数量）
4. 测速过程中界面**不会卡死**，可以继续拖动窗口
5. 测速结束后，结果表格按**综合评分排名**显示（V1.3）：评分高的在前，失败 IP 在最后
6. **（V1.4 可选）** 想进一步确认「是不是一直都快」，再做一次**稳定性复测**（见下一节）
7. 点击表头也可以手动排序（数字列按真实数值排序，不是按文字排序）

### 三级测速流程（V1.2 新增）

每个 IP 依次执行三个阶段，前一级失败则后面的阶段自动跳过：

```text
TCP 443 握手（1000 ms）
 ↓ 通过
HTTPS 请求 /__down?bytes=0（3000 ms，验证 HTTP 层可用，几乎不消耗流量）
 ↓ 通过
HTTPS 下载 /__down?bytes=1048576（10000 ms，统计下载速度）
```

- HTTPS 请求的 SNI 与 Host 均使用 `speed.cloudflare.com`（Cloudflare 官方测速域名），
  因此对 Cloudflare IP 段的测速结果最准确；
- 端口 443 / 2053 / 2083 / 2087 / 2096 / 8443 走 HTTPS，
  80 / 8080 / 8880 / 2052 / 2082 / 2086 / 2095 走明文 HTTP；
- 下载测试独立发起新连接（不复用 HTTP 测试的连接），每次测速都是完整真实的一次请求。

### 综合评分与排名（V1.3 新增）

只有**下载测速成功**的 IP 才参与评分（0 ~ 100 分），公式在 `core/score.py`：

| 指标 | 权重 | 方向 | 说明 |
| --- | --- | --- | --- |
| TCP 延迟 | 25% | 越低越好 | ≤50ms 满分，≥1000ms 0 分 |
| HTTP 延迟 | 20% | 越低越好 | ≤100ms 满分，≥3000ms 0 分 |
| 下载速度 | 45% | 越高越好 | ≥5MB/s 满分，≤10KB/s 0 分 |
| 稳定性 | 10% | — | V1.4 起由**稳定性复测**的真实数据参与（见下一节），未复测时以「HTTP 拿到正常状态码」兜底 |

- 每项先**对数归一化**再加权，避免一个极端高速 IP 把其他 IP 全部压成低分；
- 排名规则（`core/ranking.py`）：成功 IP 按评分降序 → 评分相同比下载速度 → 再相同比 TCP 延迟；
  失败 IP 永远排在最后且不占名次；
- 结果区上方可按 **最低速度 / 最大TCP延迟** 筛选，**显示** 下拉框切换 TOP 10 / 20 / 50 / 100
  （默认 TOP 100，有效 IP 不足时显示全部），改完点 **【应用筛选】** 立即重新排名。

### 稳定性复测与最终排名（V1.4 新增）

测速结束后，结果区下方出现 **稳定性复测** 区域：对当前 V1.3 排名里**评分有效的 TOP IP**
再重复测试多轮，用真实的多次结果判断「这个 IP 是不是一直都快」。

| 选项 | 可选值 | 默认 | 说明 |
| --- | --- | --- | --- |
| 复测轮数 | 3 / 5 / 10 次 | 5 次 | 每个 IP 重复测几次；次数越多结论越稳，用时越长 |
| 复测并发 | 10 / 20 / 50 | 20 | 复测时同时测试几个 IP；越大越快，对网络压力越大 |

操作步骤：

1. 先完成一次测速（得到 V1.3 排名）；
2. 在 **稳定性复测** 里选好轮数与并发，点 **【开始复测】**（测速中或没有有效 IP 时按钮是灰的）；
3. 观察进度条与状态行：`第 X/Y 轮，已测 a/b`、`当前：IP`；
4. 复测中可随时点 **【停止复测】**，已完成的轮次结果**会被保留并参与最终排名**；
5. 复测结束后表格按**最终评分**重新排名，弹窗显示稳定 IP 数量、平均稳定性、最高最终评分与 TOP10。

**稳定性评分（0 ~ 100）**，公式在 `core/stability.py`：

| 指标 | 满分 | 说明 |
| --- | --- | --- |
| TCP 成功率 | 20 分 | 多轮里 TCP 连上的比例 |
| HTTP 成功率 | 20 分 | 多轮里 HTTP 正常响应的比例 |
| 下载成功率 | 20 分 | 多轮里下载成功的比例 |
| TCP 延迟稳定 | 20 分 | 变异系数 CV ≤ 15% 满分，≥ 60% 0 分 |
| 下载速度稳定 | 20 分 | 变异系数 CV ≤ 20% 满分，≥ 100% 0 分 |

> 波动用 **变异系数 CV = 标准差 ÷ 平均值** 衡量：CV 越小说明每轮结果越接近，也就是越稳定。
> 只有 1 轮数据时无法计算波动，表格里显示 `--`。

**最终评分与最终排名：**

```text
最终评分 = V1.3 综合评分 × 0.9 + 稳定性评分 × 0.1
```

- 排名规则（`core/ranking.py`）：按最终评分降序 → 再比稳定性评分 → 再比 V1.3 综合评分；
- **V1.3 的评分与排名完全保留**：表格里 `排名` / `综合评分` 两列仍是 V1.3 的值，
  复测结果放在 `稳定性` / `最终评分` / `最终排名` 等新列里；
- 复测只覆盖 TOP 集合，因此复测后表格只显示**参与复测的 IP**（按最终名次排列）；
- 一旦重新点【应用筛选】或重新测速，旧的复测结果就会失效（需要重新复测）。

### 稳定性导出（V1.4 新增）

复测完成后，稳定性区域出现 2 个按钮：

| 按钮 | 作用 |
| --- | --- |
| 【导出稳定TOP TXT】 | 按**最终排名**取前 100 的 IP 保存到 `output\IP优选_稳定TOP100_日期时间.txt`（每行一个） |
| 【导出稳定性CSV】 | 保存完整复测统计到 `output\IP优选_稳定性结果_日期时间.csv`（含轮数/各阶段成功率/CV/稳定性评分/最终评分/最终排名） |

> V1.4 起，【复制TOP10/50/100】在复测完成后会优先按**最终排名**复制（稳定者优先）。

### 一键复制与导出（V1.3 新增）

测速结束后结果区下方会出现 5 个按钮：

| 按钮 | 作用 |
| --- | --- |
| 【复制TOP10】/【复制TOP50】/【复制TOP100】 | 把前 N 名 IP 复制到剪贴板，每行一个、不带其他文字 |
| 【导出TXT】 | 保存 TOP100 到 `output\IP优选_TOP100_日期时间.txt`（每行一个 IP） |
| 【导出CSV】 | 保存完整结果到 `output\IP优选_结果_日期时间.csv`（含排名/延迟/状态/评分，UTF-8-BOM 编码，Excel 直接打开不乱码） |

### 结果摘要（V1.3 新增）

测速结束后表格下方显示一行摘要：
`有效IP | 最快速度 | 平均速度 | 最低延迟 | 平均TCP延迟 | 平均HTTP延迟 | TOP1（评分）`

复测完成后，稳定性区域下方还会多显示一行**复测摘要**：
`稳定IP | 波动IP | 平均稳定性 | 最高最终评分 | TOP10`（稳定性评分 ≥ 60 视为「稳定」）。

### 停止

- 测速过程中点 **【停止测速】**：不再创建新任务，正在进行的连接安全结束，已得到的结果保留并显示；
- 复测过程中点 **【停止复测】**：已完成的轮次结果保留，并据此生成最终排名；
- 两种情况按钮状态都会自动恢复，可以重新测速 / 重新复测。

### 结果字段说明

| 字段 | 说明 |
| --- | --- |
| 排名 | 综合排名（V1.3）；测速中或失败显示 `--` |
| IP | 目标 IP |
| 端口 | 实际测试的端口 |
| TCP延迟 | TCP 握手耗时（毫秒）；失败显示 `--` |
| HTTP状态 | HTTP/HTTPS 响应状态码（如 `200`）；未测试显示 `--` |
| HTTP延迟 | 从发出请求到收到响应头的耗时（毫秒） |
| 下载速度 | 下载测速结果，如 `1.25 MB/s`；未测试显示 `--` |
| 综合评分 | 0 ~ 100（V1.3）；≥80 绿色、≥50 橙色、其余红色；无评分显示 `--` |
| 稳定性 | 0 ~ 100（V1.4，多轮复测得出）；≥80 绿色、≥50 橙色、其余红色；未复测显示 `--` |
| TCP成功率 | 复测里 TCP 连上的比例（如 `100%`）；无复测数据显示 `--` |
| HTTP成功率 | 复测里 HTTP 正常响应的比例；无复测数据显示 `--` |
| 下载成功率 | 复测里下载成功的比例；无复测数据显示 `--` |
| TCP波动 | TCP 延迟的变异系数（如 `±8%`）；轮数不足 2 无法计算时显示 `--` |
| 下载波动 | 下载速度的变异系数；轮数不足 2 无法计算时显示 `--` |
| 最终评分 | `V1.3综合评分 × 0.9 + 稳定性 × 0.1`（V1.4）；未复测显示 `--` |
| 最终排名 | 按最终评分排出的名次（V1.4）；未复测显示 `--` |
| 状态 | `全部成功` / `HTTP失败（原因）` / `TCP失败（原因）` |

鼠标悬停在 IP 上可以看到失败的具体原因；复测后悬停还会显示 V1.3 评分、稳定性评分、复测轮数与 TCP 延迟区间。

## 9. 如何测试

在项目根目录执行全部单元测试：

```bash
python -m unittest discover -s tests -v
```

只运行某一个测试文件：

```bash
python tests/test_ip_loader.py
python tests/test_ip_validator.py
python tests/test_cidr_generator.py
python tests/test_cloudflare_source.py
python tests/test_http_tester.py
python tests/test_score.py
python tests/test_ranking.py
python tests/test_export.py
python tests/test_stability.py
```

测试内容：

- **IP 读取**：正常 IP、`IP:端口`、空行、注释、重复 IP、格式错误、空文本、空文件
- **文件读取**：UTF-8、带 BOM 的 UTF-8、GBK、文件不存在、传入目录
- **IP 验证**：正常 IPv4、非法 IPv4、私有 IPv4、`127.0.0.1`、IPv6、组播、保留地址
- **导入统计**：`读取数量 = 有效 + 重复 + 无效`
- **CIDR 随机生成**：网段解析、按指定数量生成、不超过上限、去重、过滤私有/回环、排除已有 IP、非法 CIDR 容错
- **Cloudflare API**：正常返回、HTTP 错误、网络超时、JSON 解析失败、缺少 `ipv4_cidrs`（全部用 mock 模拟，**单元测试不依赖真实网络**）
- **HTTP / 下载测速（V1.2）**：TLS 握手、状态码解析、2xx/3xx 成功、404 失败、超时、下载字节数与速度统计、错误分类（本地 mock 服务器，**不依赖真实网络**）
- **综合评分（V1.3）**：各指标归一化、权重边界（满分 / 0 分 / 中间值）、评分范围 0~100
- **综合排名（V1.3 / V1.4）**：评分降序、同分比速度再比延迟、失败 IP 沉底不占名次、
  筛选（最低速度 / 最大延迟）、TOP N 截断、`compute_final_score` 取整与边界
- **导出（V1.3 / V1.4）**：TXT 每行一个 IP、TOP N 截断、CSV 字段完整、UTF-8-BOM 编码、空列表不报错
- **稳定性（V1.4）**：成功率统计、变异系数 CV 计算、`_cv_score` 的满分/零分/中间值、
  满轮与部分轮（停止复测）两种情况下的稳定性评分与最终排名（**不依赖真实网络**）

## 10. 常见错误

| 现象 | 原因 | 解决方法 |
| --- | --- | --- |
| `python 不是内部或外部命令` | 没有安装 Python 或未加入 PATH | 重装 Python 并勾选 **Add python.exe to PATH**，然后重开终端 |
| 运行 `python` 打开了应用商店 | 系统中的“应用执行别名”占位程序 | 设置 → 应用 → 高级应用设置 → 应用执行别名 → 关闭 `python.exe` / `python3.exe` |
| `ModuleNotFoundError: No module named 'PySide6'` | 没有安装依赖 | 执行 `python -m pip install -r requirements.txt` |
| 安装 PySide6 时下载很慢 / 中断 | 完整 PySide6 包较大 | 见上文「下载太慢怎么办」，改用 `PySide6-Essentials` |
| `ModuleNotFoundError: No module named 'core'` | 没有在项目根目录运行 | 先 `cd` 到项目根目录，再执行 `python main.py` |
| 提示「IP 文件不存在」 | 文件被移动或删除 | 重新点击【选择IP文件】选择正确的文件 |
| 提示「文件编码无法识别」 | 文件是特殊编码 | 用记事本另存为 **UTF-8** 编码后重试 |
| 提示「没有可用的公网 IPv4 地址」 | 导入的 IP 都是私有 / 非法 / IPv6 | 检查导入内容，第一阶段只支持公网 IPv4 |
| 提示「网络连接错误（本机配置了系统代理 127.0.0.1:1819：请确认代理软件已启动）」 | **最常见**：本机配了系统代理，但代理软件（Clash / v2ray 等）没启动或节点失效 | 启动代理软件并确认节点可用，然后再点【测试Cloudflare连接】 |
| 提示「网络连接错误」 | 没有网络、防火墙拦截、DNS 解析失败 | 检查网络后重试；仍失败可改用手动导入（不影响其他功能） |
| 提示「HTTP 状态码：XXX」 | Cloudflare 接口临时故障或被网络设备拦截（如 403 / 429 / 503） | 稍后重试；先点【测试Cloudflare连接】看具体状态码 |
| 提示「JSON 解析失败」 | 返回内容不是预期的 JSON（常见于被劫持或被安全网关替换页面） | 检查是否有网络劫持 / 公司网关；先点【测试Cloudflare连接】 |
| 提示「API 返回异常（缺少 ipv4_cidrs）」 | 接口返回格式变化 | 稍后重试；接口地址与数据格式见 Cloudflare 官方文档 |
| 提示「网络连接超时」 | 网络较慢、代理不通 | 稍后重试；先点【测试Cloudflare连接】；或先手动导入，不影响其他功能 |
| 全部显示 `失败（timeout）` | 网络不通、IP 不可用、超时太短 | 增大超时（如 2000~3000 ms），或更换可用 IP |
| 提示「连接被拒绝」 | 目标端口没有开放 | 换端口（常见 443 / 2053 / 8443）或换 IP |
| 部分行显示 `HTTP失败（TLS握手失败…）`（V1.2） | 少数 IP 的 TLS 握手异常（服务端拒绝、证书链不完整等） | 属正常现象；这部分 IP 已计入 HTTP 失败统计，可直接忽略或重测 |
| 下载速度列全部为 `--`（V1.2） | 未勾选【下载测试】，或全部 IP 都没通过 TCP / HTTP 阶段 | 勾选【下载测试】后重测；或先用更大超时重测 |
| 界面卡住不动 | 极少见（例如系统防火墙拦截大量连接） | 点击【停止测速】，降低并发（如 20）后重试 |
| 【开始复测】按钮是灰色（V1.4） | 还没测速、排名里没有「下载成功」的 IP，或正在测速 / 正在复测 | 先完成一次测速并确认有综合评分；等当前任务结束后再点 |
| 复测后表格只剩少量行（V1.4） | 复测只覆盖 V1.3 排名里的 TOP IP，表格就只显示这些 IP | 属正常现象；点【应用筛选】或重新测速可回到完整列表 |
| 复测后 `稳定性` / `最终评分` 全是 `--`（V1.4） | 复测没有拿到有效数据（全部超时 / 刚开始就被停止） | 检查网络后重试；或放宽 HTTP / 下载超时后再复测 |
| `TCP波动` / `下载波动` 显示 `--`（V1.4） | 有效轮数不足 2 轮，无法计算变异系数 | 增加复测轮数（如 5 或 10 次）后重测 |
| 稳定性评分普遍偏低（V1.4） | 目标 IP 本身波动大，或下载超时太短导致部分轮次失败 | 适当增大下载超时 / 降低复测并发，再复测观察 |
| 想查看详细原因 | — | 打开 `logs/app.log` 查看日志 |

## 11. 日志说明

- 日志文件：`logs/app.log`（UTF-8，单个文件最大 2MB，自动保留 3 个备份）
- 记录内容：软件启动、IP 导入、自动获取（CIDR 数量 / 候选 IP）、开始测速、测速完成、
  开始复测 / 复测完成（目标 IP 数 / 轮数 / 并发 / 用时 / 是否用户停止）、导出、异常和错误
- 不会记录任何敏感信息（本项目也不收集用户个人信息）

### 自动获取失败时，日志里有真实原因

界面上只显示**简短的中文提示**（例如「网络连接错误」），
而**真实错误**（异常类型 + 原始信息）会完整记录到 `logs/app.log`，方便排查：

```text
2026-09-18 22:57:25 [INFO] ip_optimizer: Cloudflare API request started: url=https://api.cloudflare.com/client/v4/ips
2026-09-18 22:57:25 [INFO] ip_optimizer: HTTP status: 200
2026-09-18 22:57:25 [INFO] ip_optimizer: response length: 4123 bytes
2026-09-18 22:57:26 [INFO] ip_optimizer: 获取 Cloudflare IPv4 网段成功（主源）：15 个 CIDR，耗时 0.76 秒

# 失败时会出现下面这类真实错误记录：
2026-09-18 22:58:01 [ERROR] ip_optimizer: connection error: <urlopen error [WinError 10061] ...>
2026-09-18 22:58:01 [ERROR] ip_optimizer: timeout error: <urlopen error timed out>
2026-09-18 22:58:01 [ERROR] ip_optimizer: JSON parse error: Expecting value: line 1 column 1 (char 0)
```

> 排查顺序建议：① 打开 `logs/app.log` 看最后几行 → ② 点界面上的【测试Cloudflare连接】→
> ③ 若日志里出现 `127.0.0.1:xxxx` 说明是**系统代理**问题，请先启动代理软件。
